| 2026-09-06 | P1-to-EVM fixed-size transport | Strip `sha256:` and decode P1 digests into `bytes32`; map exact validated prefixed identifiers to `sha256(UTF8(identifier))` and name those fields `*IdHash`/`*VersionHash`. Solidity does not parse canonical JSON. | Active |

| 2026-09-06 | Bind P5 EIP-712 to the deployed P4 registry | Domain `Rovaulta`/`1`, Sepolia `11155111`, and the verified registry artifact prevent chain, contract, and unrelated-domain reuse. Full typed data also carries every exact release binding and the P1 intent digest. | Active |
| 2026-09-06 | Keep replay authority durable and offchain | One API instance owns a SQLite compare-and-set nonce store and performs exact P4 reads both before signing and before consumption. This is honest single-node replay protection, not an onchain nonce claim. | Active |
| 2026-09-06 | Fail closed on Ledger signer-kit legacy fallback | Current Signer Kit may expose `SIGN_TYPED_DATA_LEGACY` when Clear Signing context is unavailable. P5 observes, cancels, and rejects that state; it never accepts hashed/blind output. | Active |
| 2026-09-07 | Require exact runtime Clear Signing filters | A successful Context Module response is insufficient: P5 requires the exact Sepolia registry, 15-field schema, declared filter count, and every exact display path before full typed-data signing may proceed. Partial or mismatched context fails closed. | Active |
| 2026-09-07 | Keep P5 agent claims evidence-bound | `/release/prepare` is an agent-facing deterministic proposal boundary, while `/p5-ledger` is a manual operator harness. No autonomous/LLM agent runtime or execution evidence is claimed in P5. | Active |
| 2026-09-07 | Keep Speculos behind the production Ledger semantics | `webhid` remains the production default; `speculos` is rejected outside development/test and accepts only a directly configured loopback endpoint. Exact EIP-712, Context Module guard, signer recovery, registry recheck, and atomic nonce consumption stay shared. The deterministic simulator signer is barred from production authorization. | Active |
| 2026-09-07 | Use active ERC-7730 v2 and fail closed on tester access | The candidate descriptor migrated to v2 and passes `erc7730 1.0.7`. Missing official Tester `GATING_TOKEN` blocks structured-display evidence, while Rovaulta signing separately needs application origin/accepted-descriptor resolution. The direct implicit test token and blind-signing fallbacks are prohibited. | Active |
| 2026-09-07 | Keep the AI deployment agent behind a host-owned capability state machine | A strict provider may extract public references and request the next allowlisted tool, but deterministic catalog resolution, live P4 reads, existing P5 preparation, browser Ledger signing, signature verification, and nonce consumption remain separate authorities. No model-created binding, payload, signature, registry write, or authorization is accepted. See ADR-0008. | Active |
| 2026-09-07 | Use a dependency-free OpenAI Responses adapter with no mock fallback | No provider SDK existed. Raw `fetch` plus strict single-function schemas supports real tool calling without a new dependency; tests inject a scripted provider explicitly. Missing key/model/catalog configuration fails closed. | Active |
| 2026-09-07 | Treat deployment prose as a finite public grammar, not provider input | The host accepts only catalog-generated whole-request forms, resolves the target before provider use, discards raw text, sends a canonical public projection with `store: false`, and requires model aliases to echo the same target. This closes conflicting-target and private-context disclosure paths without granting the model authority. | Active |
| 2026-09-09 | Issue Sepolia clearances only through an explicit account-backed operator command | The command lifts exact bindings from an account-owned public `CLEAR` evaluation, reuses the P1/P4 transport, checks the deployed authorized registrar, simulates before broadcast, validates both public registry events, and performs exact readback. It does not auto-issue from evaluations, store private keys in the API, or fabricate Graph entities. | Active |
| 2026-09-09 | Keep P13 setup HTTP-only and public-result-only | The account runner composes existing authenticated APIs and polls the owning account; it never opens SQLite, imports P2/P7, or exposes policy/blind material. A separate local provisioning command may read the encrypted policy through `ApplicationStore` and pass the exact versioned payload in memory to the official CRE CLI, but never sends it over HTTP or writes it to evidence. CRE deployment, Vault provisioning, and callback delivery remain explicit operator boundaries. | Active |
| 2026-09-09 | Resolve account-simulation CRE artifacts from the temporary workflow root | CRE CLI v1.32.0 resolves a temporary workflow's `workflow-path` and `config-path` from the directory containing its generated `workflow.yaml`, even with `-R .`. Repository-root-relative paths therefore fail artifact validation; paths calculated from the temporary workflow directory reach compilation and execution. The executor keeps the source/config files authoritative and removes the temporary workflow after every result. | Active |
| 2026-09-09 | Require an explicit CRE authentication preflight | The account simulation executor runs `cre -v` and `cre whoami` before workflow execution, discards their output, and fails closed on a missing or expired session. This prevents an account evaluation from being labeled official simulation when the authenticated CLI cannot run. | Active |
