# Demo Acceptance Contract

A final demo is not ready until a viewer can see this causal chain without trusting narration:

1. Build A attempts evaluation against a hidden rule set.
2. Evaluation is denied without exposing the hidden rule.
3. Build B is evaluated and cleared.
4. Public clearance metadata is visible and bound to Build B.
5. A deployment is prepared but cannot proceed without Ledger approval.
6. Human approves on the physical device.
7. Deployment proceeds in the digital twin.
8. Build B is mutated; the old clearance no longer authorizes it.

Each transition must be driven by real project state, not a hard-coded animation.
