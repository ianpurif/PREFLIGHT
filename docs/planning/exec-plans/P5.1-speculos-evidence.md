# P5.1 — Official Ledger Speculos Evidence

## Outcome

Preserve the production WebHID/DMK/Ethereum Signer Kit path while adding a narrow official DMK
Speculos transport for test/demo execution. The same exact EIP-712 request, Clear Signing checks,
authorized-signer policy, registry recheck, nonce consumption, and release authorization semantics
must apply to both transports. Capture only evidence actually produced by the official Speculos
device simulator and keep physical Ledger evidence open.

## Non-goals

- physical Ledger, Secure Element, hardware root-of-trust, or physical Clear Signing claims
- weaker local signing, JavaScript signer mocks as final evidence, blind/hashed/personal signing,
  backend key custody, or removal of the production origin-token requirement
- P6 activation, digital twin, robot controls, or architecture redesign
- assuming Ledger prize acceptance of Speculos-only evidence

## Invariants

- `webhid` remains the production transport and requires explicit browser permission, issued origin
  token, accepted descriptor, active Ethereum app, and on-device address confirmation.
- `speculos` uses Ledger's official DMK Speculos transport and an actual Ethereum app binary under
  Speculos; it is always labeled a simulator, rejected outside development/test, and its
  deterministic signer is never production-authorized.
- Both transports call one shared strict full-EIP-712 signing path. All 15 exact fields, Sepolia
  `11155111`, registry `0xFB270cc222efa8B5005AA097dD512Be2558dde65`, authorized signer, nonce,
  expiry, post-sign registry check, and atomic consumption remain unchanged.
- Local descriptor injection, if supported by Ledger's official test tooling, is confined to the
  Speculos test boundary. Production Clear Signing requirements cannot be weakened globally.
- Cases A–F control the actual Speculos UI for approval/rejection; direct mock signatures are not
  evidence.
- Missing Docker/Speculos, Ethereum app binary, Tester gating token, application origin/accepted
  descriptor, or official tester access is an
  explicit environment blocker, never fabricated success.

## Change surfaces

- `packages/ledger-gate`: narrow transport selection/factory, official Speculos transport, shared
  signer lifecycle, and adapter regressions
- test/evidence tooling: Speculos lifecycle, actual UI control, A–F orchestration, safe screenshots,
  and ERC-7730 validation/tester commands
- root configuration/scripts: exact pinned dependency and opt-in commands only
- planning, architecture, Ledger partner/DX, compliance, verification, evidence, and AI-use docs
- `apps/api` and `packages/chain-client`: reuse unchanged release semantics; modify only if an
  evidence harness needs a narrow injectable boundary without weakening production

## Acceptance checks

- Current official Speculos transport builds beside WebHID and selects only `webhid | speculos`.
- The Speculos signer uses the same prepared request parser and `runStrictTypedDataAction` path.
- Official ERC-7730 schema validation passes for the exact descriptor.
- Official Clear Signing Tester renders the exact structured display under Speculos, or the exact
  missing gating/tool prerequisite is recorded.
- Actual Speculos UI drives A approval and B rejection; C/D block before signer; E rejects replay;
  F rejects post-sign mutation.
- A–F evidence includes exact versions/model/app identity and contains no seed, token, credential,
  private key, PIN, confidential envelope, or blind.
- WebHID compilation/tests and all P1–P5 repository gates remain green.
- Status is recorded verbatim: `Official Speculos integration: COMPLETE`, `Physical Ledger
  execution: NOT PERFORMED — hardware unavailable`, and `Ledger prize acceptance of Speculos-only
  execution: AWAITING PARTNER CONFIRMATION` only if official Speculos integration genuinely runs.

## Risks and rollback

- Docker is not installed on the Windows host. Native WSL2 Speculos now works with QEMU and the
  public official Ethereum ELF, but the official Tester wrapper retains separate Docker/tooling
  assumptions.
- Ledger's Clear Signing Tester requires a gating token. The exact missing-access error is recorded.
- The Tester discards its signature; Rovaulta A/B/E/F separately require legitimate application
  origin/accepted-descriptor resolution or another official signature-preserving test path.
- Speculos does not emulate Ledger OS/Secure Element security and cannot close physical evidence.
- The deterministic Speculos signer and any related clearance/nonce state are public test data and
  prohibited from production policy.
- Rollback is confined to the P5.1 transport/evidence slice; P1–P5 production semantics and P6 stay
  untouched.

## Decisions / deviations

- Prefer Ledger's published `@ledgerhq/device-transport-kit-speculos` factory over custom APDU or
  legacy LedgerJS transports.
- Prefer an official published/prebuilt Ethereum app artifact. Do not commit a binary or seed unless
  Ledger's distribution and repository policy explicitly support it.

## Verification evidence

Speculos `0.27.0` ran the checksum-verified public Ethereum `1.22.3` Nano S Plus ELF under WSL2.
The official DMK Speculos transport discovered it, requested the Sepolia address with on-device
confirmation, and the official controller drove the actual emulator buttons. The descriptor was
migrated to ERC-7730 v2 and `erc7730 1.0.7` reported no issues.

On 2026-09-11 the clean emulator was restarted and the repository smoke command passed again. The
authenticated `/p5-ledger` browser route prepared the exact public intent against Sepolia block
`11679749`; a public build-digest mutation was rejected as `MALFORMED_REQUEST` before signer
invocation. The valid path stopped at `CLEAR_SIGNING_UNAVAILABLE` because the Ledger-issued origin
token and accepted/served descriptor are unavailable. See
`docs/compliance/evidence/p5-ledger-speculos-browser-boundary-2026-09-11.md`.

The official registry Tester wrapper then exited `1` with exactly
`Error: GATING_TOKEN environment variable not set`. The implicit direct-tester token was not used,
blind signing was not enabled, and A/B/E/F were not relabeled from local mock tests. The real P5
prepare route returned `CLEARANCE_BINDING_MISMATCH` for C and `CLEARANCE_NOT_FOUND` for D before
signer invocation. See
`docs/compliance/evidence/p5-ledger-speculos-partial-2026-09-07.md`.
