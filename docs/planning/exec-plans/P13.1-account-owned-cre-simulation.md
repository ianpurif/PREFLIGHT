# P13.1 — Account-owned authenticated CRE simulation mode

## Outcome

Allow the existing authenticated account lifecycle to run one account-created evaluation through
the already-qualified official `cre workflow simulate` command, then persist the validated public
result with explicit simulation provenance. The existing P12 operator command can consume that
account-owned `CLEAR` result without changing the registry or the P13 confidential workflow.

## Non-goals

- No changes to `handlerInTee`, workflow configuration, fixtures, secret semantics, or P13
  qualification evidence.
- No live CRE/DON deployment, callback, Early Access, or Ledger work.
- No P2 fallback, fixture import, direct SQLite bootstrap, manual callback, or fabricated result.
- No automatic Sepolia broadcast; issuance remains the explicit P12 operator command.

## Invariants

- Account/site/robot/build ownership is established by the existing authenticated HTTP routes.
- The simulation executor invokes the official CLI only; CLI failure is a closed failure.
- The public payload, request-scoped `secretsNames` mapping, and confidential env file are derived
  from the exact account request and policy, are temporary, and are deleted after execution.
- The result passes the existing CRE callback parser and exact P1 binding checks before persistence.
- Persisted evaluations identify `official-cre-cli-simulation`; they never claim live CRE/DON execution.
- No confidential envelope, blind, CLI output, credential, or secret is returned or written to evidence.
- P12 remains the only path that constructs and broadcasts a Sepolia clearance.

## Change surfaces

1. `apps/api/src/evaluation/` — official CLI simulation executor and execution-mode metadata.
2. `apps/api/src/application/store.ts` — persist public simulation provenance on new evaluations and
   callback results without weakening account/binding checks.
3. `apps/api/src/index.ts` / `.env.example` — explicit environment-selected executor mode; gateway
   remains the default.
4. `apps/api/scripts/p13-account-evaluation.ts` / `apps/api/package.json` — report and validate
   simulation provenance for the existing account operator flow.
5. `apps/api/test/` — parser/executor and persistence regression coverage.
6. `apps/api/README.md`, `README.md`, planning/evidence docs — truthful operator runbook and state.

## Acceptance checks

- With `ROVAULTA_CRE_EXECUTION_MODE=simulation`, a real authenticated account request invokes the
  official CLI workflow with account-derived public payload and temporary account-derived secret.
- A successful CLI `EVALUATED/CLEAR` result is stored under the owning account and contains
  `executionMode: official-cre-cli-simulation` (and CLI version when available).
- A malformed, mismatched, rejected, nonzero, or confidential-leaking CLI result is not persisted.
- Existing gateway mode and callback tests continue to pass unchanged in behavior.
- The persisted result is accepted by `record:sepolia-clearance` only when it is `CLEAR` and all
  existing P1/P4 checks pass.
- No live CRE claim is added to Chainlink evidence.

## Verification

- Targeted API simulation-executor, lifecycle, callback, and clearance tests.
- API typecheck and lint; official CLI simulation when available.
- Full repository verification and `git diff --check`.
- Read-only independent review focused on provenance confusion, temp-secret cleanup, CLI output
  leakage, account binding, and accidental gateway fallback.

## Rollback

The mode is selected only by environment. Removing the simulation executor/factory branch restores
the existing gateway-only behavior; no database or contract migration is required.
